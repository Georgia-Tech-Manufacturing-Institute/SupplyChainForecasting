Plant Database Schema

Each plant gets its own SQLite file at data/processed/{plant}.db, created by sql_setup() in app/core/loader.py. All plants share the six tables below.

No foreign keys

Tables relate only through part and the week indices orderidx (week demanded or consumed) and predidx (week the forecast was released). SQLite enforces none of these links, so a part can exist in one table and be missing from another. filter_disjoint() trims those parts at dataset time.

Dedup is by key, not by filter

Every insert goes through INSERT OR IGNORE. Overlapping waterfall extracts are absorbed by the UNIQUE keys, and re-loaded transactions are rejected by the trans_number primary key. The only upsert is the additive one into consumption_agg.

loaded_files is per week

Its key is (data_type, week_idx), not the filename. A waterfall extract writes one row per release week it covers, and a consumption load writes one per closed order week. The loaders read it back to skip weeks that are already closed. cost loads are not logged.

Schema version

SCHEMA_VERSION = 1 moved the old pre-aggregated consumption into consumption_agg. The migrate_schema() call in sql_setup() is currently commented out, so a v0 database opened now keeps its old consumption table.
